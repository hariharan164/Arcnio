Live Production Count — HD2020 LED Panel

  • 64×48 pixel industrial LED display — floor-mounted factory visibility
  • Shows real-time fabric count, shift target, and machine status
  • Data received from central server via HTTP GET polling
  • Auto-refreshes every 3–5 seconds — always live
  • Built using Python + HDSDK.dll via ctypes low-level interface
  • Deployed at C.R Garments printing unit floor — Tirupur
Python 3.x ctypes HDSDK.dll HTTP GET JSON 64×48 px
▸ HTTP Request Format
GET /api/status HTTP/1.1
Host: 192.168.1.100:3000
Accept: application/json

▸ Response 200 OK
{ "count": 248, "target": 500, "status": "RUNNING" }
▸ Client Python Code Python 3 / ctypes
# Fetch status & push to HD2020 LED Display
import requests, ctypes
resp = requests.get("http://192.168.1.100:3000/api/status").json()

# Call industrial DLL via ctypes
hdsdk = ctypes.WinDLL("HDSDK.dll")
hdsdk.SendText(resp["count"], resp["status"])
LED Panel is a passive consumer — pull-based model via HTTP GET polling · Refresh: 3–5 seconds

Vision-Based Fabric Counting

  • UV camera mounted above conveyor / printing machine exit
  • Detects each fabric piece passing through via computer vision
  • Count data sent to central server via HTTP POST in real time
  • No manual counting — zero human error, fully autonomous
  • Tech stack: OpenCV + Python image processing pipeline
  • Triggers LED panel update on every new count event
OpenCV Python HTTP POST UV Camera JSON
▸ HTTP Request Format
POST /api/count HTTP/1.1
Content-Type: application/json

▸ Body
{ "count": 1, "machine_id": "PRINT-01" }

▸ Response 201 Created
{ "status": "recorded", "total": 249 }
▸ OpenCV Python script OpenCV / Requests
# Send event on fabric edge detection crossing
import cv2, requests
if fabric_detected:
    requests.post("http://192.168.1.100:3000/api/count", json={
        "count": 1, "machine_id": "PRINT-01"
    })
UV Camera is an active producer — push-based model via HTTP POST on every fabric detection event
Slide 05 / 08 Arcnio Engineering

Pick & Place — Printing to Curing Machine

  • Robotic arm picks fabric from printing machine output tray
  • Places it onto curing machine conveyor automatically
  • Eliminates manual transfer — faster throughput, zero fabric damage
  • Arm receives job trigger via HTTP POST from central controller
  • Compatible: myCobot Pro 600 / Dobot CR5 / UR5e
  • Vacuum gripper for safe, no-contact fabric handling
myCobot Pro 600 Dobot CR5 UR5e HTTP POST Vacuum Gripper
▸ HTTP Request Format
POST /api/pick HTTP/1.1
{ "action": "pick_and_place", "gripper": "vacuum" }

▸ Response 200 OK
{ "status": "ok", "eta_ms": 3200 }
▸ Robotic Controller Client Javascript Fetch
# Express server commands robotic arm
fetch("http://192.168.1.101:8080/api/pick", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ action: "pick_and_place" })
});
Central server triggers arm on every successful fabric detection — fully synchronized automated loop
